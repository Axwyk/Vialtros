[ERROR #002] - 27 de Abril de 2026
────────────────────────────────────────────────────
FECHA: 27/04/2026 - 14:15 PM
UBICACIÓN: Frontend Console (DevTools) - Múltiples endpoints
TIPO: HTTP 401 Unauthorized

DESCRIPCIÓN:
Errores 401 (Unauthorized) en las siguientes peticiones:
  - GET http://localhost:8000/api/monitoring/ [401]
  - GET http://localhost:8000/api/routes/ [401]
  - GET http://localhost:8000/api/tracking/ [401]
  - GET http://localhost:8000/api/users/ [401]
  - Múltiples endpoints devolvieron 401

CAUSA RAÍZ:
El interceptor de axios (frontend/src/services/api.js) tenía un bug lógico:
- Cuando REACT_APP_ALLOW_LOCAL_ACCESS=true (modo dev local):
  - Se usaba un token ficticio ("local-dev-access")
  - NO se agregaba el header Authorization a las peticiones
  - El backend rechazaba las peticiones sin token válido
  
Lógica defectuosa en el interceptor:
```
if (token && isLocalAccessEnabled() && isLocalAccessToken(token)) {
  // FALTA: agregar Authorization header aquí
  return config;  // ← Se retornaba sin header
}
```

SOLUCIÓN:
✓ Fix #1: Corregir interceptor en frontend/src/services/api.js
  - Agregar Authorization header incluso para tokens locales
  - Línea a cambiar: Dentro del bloque isLocalAccessToken()

✓ Fix #2: Deshabilitar modo local-access en desarrollo
  - Crear archivo frontend/.env con REACT_APP_ALLOW_LOCAL_ACCESS=false
  - Esto obliga a usar JWT real desde el backend

✓ Fix #3: Crear usuario admin en la BD
  - Ejecutar: python manage.py shell
  - Crear superuser: admin / admin123
  - Esto genera un JWT válido al hacer login

✓ Fix #4: Crear archivo backend/.env
  - DJANGO_SECRET_KEY=django-insecure-dev-only-change-in-production
  - DJANGO_DEBUG=True
  - DJANGO_ALLOWED_HOSTS=localhost,127.0.0.1
  - CORS_ALLOW_ALL_ORIGINS=True

ARCHIVOS MODIFICADOS:
  1. frontend/src/services/api.js
  2. frontend/.env (creado)
  3. backend/.env (creado)
  4. Backend database (usuario admin creado)

RESULTADO: ✓ RESUELTO
Las peticiones API ahora incluyen Authorization header válido.
El login con admin/admin123 genera un JWT que permite acceso a endpoints.

PASOS PARA REPRODUCIR:
1. Reiniciar frontend (npm start en carpeta frontend/)
2. Ir a login page
3. Usar credenciales: admin / admin123
4. Verificar en DevTools que no hay errores 401
